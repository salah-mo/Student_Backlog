# W00-03: Write Your Working Agreement — AI Protocol, Definition of Done, and Language Conventions

> **ID:** W00-03 | **Week:** 0 | **Type:** Setup

## Objective

Before you start writing project code, you and your mentor need written agreements that define how you will work for the entire program. In this task, you will write down four agreements in your README: how you use AI tools, what privacy and licensing rules you follow, what "done" means for every task, and what language you use for commits and code reviews. You will also get a first look at build tools. These agreements exist so that good habits are decided once, on day one, instead of being re-debated every week.

## Requirements

### 1. AI usage workflow

Write down the workflow you must follow whenever you think about using AI:

1. First, attempt the work independently — this always comes first for core learning.
2. If you are stuck, request an explanation, a hint, a review, or debugging help.
3. Verify any AI output before you keep it (test it, check it against documentation, or explain why it is correct).

### 2. AI usage tiers

Document the four tiers below in your README, exactly as agreed:

- **Tier 0 (AI-free)** — applies to: fundamentals drills, Gate 1A, the first attempt on every Assiut problem, all Gates and live re-derivations, and the decomposition step.
- **Tier 1 (AI as explainer/quizzer only, no code generation)** — allowed only after an attempt; this is the default tier for W1–W5.
- **Tier 2 (AI as reviewer or hint-giver; every suggestion must be verified)** — applies from W4–W5.
- **Tier 3 (AI-assisted implementation for retained code)** — applies from W14; requires a student-designed test (Stage 3) and an AI-off modification afterwards.

State clearly that tiers apply **by activity, not by week**, and that the active tier for each task is agreed during the weekly review.

### 3. Privacy and licensing rules

- Write down that you will never share secrets, API keys, private/confidential code, or personal data — with AI tools or anywhere else.
- Add a rule that before using any external code or library, you check its sources, licenses, dependencies, and security.

### 4. Definition of Done (DoD)

Write your own DoD: a concrete checklist that every future task must satisfy before you mark it complete. For example:

- Code runs without errors
- Acceptance criteria are met
- Tests pass
- Commit messages are in English
- Documentation is updated
- You can explain every line you kept

Make each item checkable, not vague.

### 5. Language agreement

- Write down that all commit messages and PR review comments must be in English.
- Decide and record the language for code identifiers and comments (English is expected, since this is an English-language agreement).

### 6. Build-tools teaser

- Read a short introduction to what build tools do (compiling, managing dependencies, running tests, packaging).
- In your README, write a short summary in your own words (5–10 sentences) of why projects use build tools and what Maven is used for. Do not install or configure Maven yet — it is introduced in W3 and used in W4–W5.

## Deliverables

- A README section (or sections) in your repository containing: the AI usage workflow, the four AI usage tiers, the privacy/licensing rules, your Definition of Done, the language agreement, and the build-tools summary.

## Acceptance Criteria

- The AI workflow, privacy/licensing rules, and DoD are recorded in the README.
- All four AI tiers are documented with what each one allows and where it applies, including the "by activity, not by week" rule and the weekly review agreement.
- You can explain, in your own words, when AI use is appropriate and how you will verify AI output before keeping it.
- The Git/language agreement is clear: English commit messages and PR comments are written down.
- The DoD is a concrete checklist, not general statements.

## Constraints

- This is a documentation-only task: do not start implementing project features or installing build tools.
- Write the agreements yourself. This is a Tier 1 activity — you may ask AI to explain concepts (e.g., "what is a build tool?"), but the README text must be your own writing, not generated output.
- Use only the tier definitions and scope given here; do not add extra rules or remove existing ones.
