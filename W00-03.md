# W00-03: Write Your Working Agreement — AI Protocol, Definition of Done, and Language Conventions

> **ID:** W00-03 | **Week:** 0 | **Type:** Setup
> **Deliverable:** README section | **Source of the agreements:** the program plan sheet (AI Protocol, DoD + LANGUAGE sections)

## Objective

Before you write any project code, you and your mentor agree in writing, from day one, on how you will work: how AI may be used, what privacy and licensing rules apply, what "done" means for every task, and what language you use for commits and code reviews. You will write these agreements into your README so they are visible and binding for the whole program, and you will create the log file that makes the AI protocol measurable. These agreements exist so good habits are decided once, on day one, instead of being re-debated every week.

## Requirements

### 1. AI usage workflow

Record the agreed workflow in your README:

1. **Independent attempt first** on core learning.
2. Then ask AI for a **hint, explanation, review, or debugging help** — AI is an explainer, hint-giver, reviewer, or debugging assistant, never a substitute for understanding.
3. **Verify every suggestion you keep** — against requirements, tests, experiments, and documentation.
4. **Re-derive or modify a related example without AI** to confirm you truly understand what you kept.

### 2. AI usage tiers

Document the four tiers, exactly as agreed:

- **Tier 0 (AI-free)** — fundamentals drills, Gate 1A, the first attempt on every Assiut problem, all Gates and live re-derivations, and the decomposition step.
- **Tier 1 (AI as explainer/quizzer, no code generation)** — used after an attempt; the default for W1–W5.
- **Tier 2 (AI as reviewer/hint-giver; every suggestion verified)** — from W4–W5.
- **Tier 3 (AI-assisted implementation for retained code)** — from W14; requires a student-designed test (Stage 3) and an AI-off modification.

State clearly in your README:

- Tiers apply **by activity, not by week**.
- The active tier for each task is agreed during the **weekly review**.
- The default is the **lowest tier that lets you make progress independently**; the tier is raised only when lower tiers are clearly insufficient.

### 3. AI usage log (`ai-log.md`)

The AI protocol includes a log. Create `ai-log.md` in your repository and describe its purpose in the file:

- One concise entry per meaningful AI-assisted decision or debugging session.
- Each entry records: the question, the useful takeaway, what you accepted/changed/rejected, and how you checked the result.
- Log AI use when it **materially influences** code, design, or debugging.

### 4. Privacy and licensing rules

Record these rules in your README:

- Never upload or share credentials, API keys, private/personal data, or confidential code.
- Before using generated or copied code, check licenses, dependency provenance, and security.

### 5. Definition of Done (DoD)

Record the agreed DoD in your README. A task is **done** when:

- The behavior meets the specification.
- Appropriate test evidence exists.
- The commit/PR follows the current workflow.
- Review is complete, where applicable.
- You can explain the implementation and the key trade-offs.

Write it as a checklist you can apply to every future task, and keep all five conditions.

### 6. Language agreement

- Record that **commit messages and PR review comments are written in English** — as a professional communication habit, not a formality.

### 7. Build-tools teaser

- Read a short introduction to what build tools do (compiling, dependency management, running tests, packaging). Prefer **official documentation first** — for example the Maven guides at `https://maven.apache.org/guides/`.
- Write a short summary in your own words (5–10 sentences): why projects use build tools and what Maven is for.
- Do not install or configure Maven — it is introduced in W3 and used in W4–W5.

## Deliverables

- A README section (or sections) in your repository containing: the AI usage workflow, the four AI usage tiers, the privacy/licensing rules, the Definition of Done, and the language agreement.
- A `ai-log.md` file, created and described, ready to receive entries.

## Acceptance Criteria

- The AI workflow, privacy/licensing rules, and DoD are recorded in the README.
- All four AI tiers are documented with their activities and week applicability, including "by activity, not by week", the weekly review assignment, and the lowest-tier default.
- You can explain, in your own words, when AI use is appropriate and how you will verify AI output before keeping it.
- The Git/language agreement is clear: English commit messages and PR review comments.
- The DoD keeps all five agreed conditions and is concrete enough to apply to any future task.
- `ai-log.md` exists and its purpose is understandable without extra explanation.

## Constraints

- This is a documentation-only task: no project features, no code, and no Maven installation.
- This task itself runs at **Tier 1**: you may ask AI to explain concepts (e.g., "what is a build tool?"), but the README and log text must be your own writing — apply the workflow you are documenting.
- Follow the program's source rule: official documentation first, explanatory articles only as secondary help.
- Record the agreements as given here; do not remove conditions or add contradicting rules.
